八天，六十次提交，两万行代码。一个 AI，学会了自己造视频。不靠模板，不靠剪辑师，从内容到成片全自动。这不是科幻，这是正在发生的事。

做短视频，最痛苦的是什么？不是不知道讲什么，而是讲出来了，做不成视频。写脚本要两小时，剪辑要两小时，配乐调音又要一小时。一个人做，每天一条就精疲力尽。我需要一个工具，能把任意内容自动变成可发布的短视频。然后我发现了 HyperFrames，它能把 HTML 变成视频。但光有渲染层不够，我需要的是一整条自动化管线。这就是 ClipForge 的起点。

ClipForge 的核心设计哲学是八个字：流程零自由度，内容最大自由度。什么意思？管线的执行顺序、质量标准、错误恢复，全部硬编码在配置文件里，AI 不能改。但每个场景讲什么、画面怎么排、用什么颜色，全部由 AI 自主推导。流程是工程的，需要确定性。内容是创意的，需要惊喜感。我们把这两种需求彻底分开，用 LETTER 和 SPIRIT 双模式管理。

整个系统分九个阶段，从环境检查到最终清理，通过 DAG 编排。内容获取、导演设计、旁白文案、音频制备、视频渲染、交付输出，每个阶段有明确的输入和产出。其中音频和素材可以并行执行。整个管线围绕一个核心指标设计：前 3 秒留存率。在短视频平台，用户划走只需要 1 到 3 秒，所以第一个场景必须是纯钩子，画面必须全片最强。

管线解决了做什么的问题，但没解决做得好不好的问题。所以我们引入了四原子约束体系：意图、边界、门禁和轨迹。意图告诉 AI 你在做什么，边界规定允许和禁止的行为，门禁自动校验产出质量，轨迹记录完整执行上下文。这套体系的核心洞察是：不要告诉 AI 不能做什么，告诉它应该做什么。更重要的是，很多规则不是从理论推导出来的，而是从实际事故中总结的。比如 CSS 动画导致全片空白、双重 padding 把内容压缩到 74%。每一个事故都催生了至少一条硬性门禁规则。

视频画面的核心矛盾是：背景要有氛围感，特效要有冲击力，但文字必须清晰可读。ClipForge 的解决方案是三层分离架构：底层背景、中间特效、顶层内容。我们用骨架加创意插槽的模式，先生成 HTML 骨架结构，再让 AI 在预留的插槽里自由填充内容。系统内置了 32 个视觉组件，涵盖背景、特效和内容三大类。动画统一使用 GSAP timeline，因为 HyperFrames 的 seek 渲染模式下 CSS animation 根本不会执行。

音画同步是最难的技术挑战。我们的方案是分段校准：先按场景分段写旁白，预估时长。然后逐段做 TTS，用实际测量时长替换预估值。HTML 中的 data-duration 唯一权威来源就是实际测量的时长，不是预估值。场景内部还通过 Phase 机制做更精细的视觉分段，找话题转换点而不是时间均分。

ClipForge 不是固定输出的工具。它从两条反馈链路中持续学习：失败闭环收紧规则，成功闭环沉淀模式。门禁失败后，归因引擎分析原因，定位违反的规则，修复重试。门禁通过后，轨迹记录完整上下文，成功分析器提取经验模式。更进一步，播放数据驱动机器评分校准，规则有 90 天老化机制，过时的经验自动清除。

回顾这八天的开发历程。第一天搭建基础管线和 DAG 定义。第三天遇到音画同步危机，催生了分段 TTS 校准机制。第四天 CSS 动画导致全片空白，催生了 185 行渲染安全规范。第五天双重 padding 事故，催生了单层 padding 铁律。第六天引擎层上线，4781 行 Python 代码。第七天三层架构重构。第八天 A/V 同步门禁加固。四个关键设计决策：状态即文件、正向规则优先、骨架加插槽、委托不重写。

最终的数据：8 天开发，60 次提交，23262 行代码变更，4781 行引擎代码，32 个视觉组件，22 种门禁检查器。支持三种视频模式，从 45 秒快讯到 10 分钟深度解析。未来计划扩展到更多领域，适配更多平台，让社区驱动的进化成为可能。

你现在看到的这条视频，就是 ClipForge 自己制作的。它用 9 个阶段的自动化管线，从内容分析到最终渲染，全程无需人工干预。这就是 ClipForge 想要证明的：通过管线编排加约束引擎加自进化反馈，AI 可以持续产出高质量的短视频内容。ClipForge 是开源的，Apache 2.0 许可证。如果你也有好内容想变成视频，欢迎来试试。VibeCoding 大赏，AI 新星计划。
