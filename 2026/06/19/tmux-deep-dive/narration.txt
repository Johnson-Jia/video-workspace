网一断，命令全没了。
有个 2007 年的老工具，能让终端会话永不掉线。它叫 tmux，一个终端复用器。一个屏幕能开多个终端，可以 detach 退到后台，再 reattach 恢复。ISC 许可，现在到了 3.7。
tmux 最巧的地方，是同一个二进制，既是客户端，又是服务器。运行时它自己决定当哪个角色。客户端连不上，就 fork 出一个服务器守护进程，用文件锁防止重复启动。用户根本不用操心怎么启动服务。
这就引出第二层：会话和终端，是彻底解耦的。session、window、pane 都活在服务器进程里，跟你的终端窗口没关系。客户端断开，只是丢了一条显示通道，状态完整保留。这才是 SSH 断线不丢任务的根。
落到代码上，是一条清晰的链路。用户终端连到 tmux 客户端，再通过 Unix 域套接字和 imsg 协议，接到服务器守护进程，整个事件循环跑在 libevent 上。对象模型是层层嵌套的：session 下面是 window，window 下面是 window_pane，再往下才是 pty，用红黑树和队列统一管理。渲染分了三层：grid 存字符，做懒分配和紧凑压缩；screen 管显示和重绘；tty 负责适配不同终端的能力。这三层，是它性能的关键。
功能层面，tmux 给得很足。会话能持久化，窗口窗格随便分，3.7 还加了浮动窗格。复制模式支持 vi 和 emacs 键位，带行号。命令系统有大约 65 条命令，可编程，配置和键绑定共用一套。还有控制模式 -CC，让 IDE 能程序化驱动它。终端能力也没落下：真彩色、256 色、Sixel 图像、OSC8 超链接、斜体，都支持。
但限制也得说清楚。平台覆盖官方 6 个，加上适配一共 11 个。强制依赖 libevent 和 ncurses，原生 Windows 不支持，只能走 Cygwin 或 WSL。还强制 UTF-8 环境，否则直接报错退出。
性能边界也得诚实讲。滚动历史一大，就会变慢，复制模式尤其明显。它还缺流控和背压机制，macOS 上复制可能有延迟。这些是社区确证的真实痛点，不是营销话术，是 worse-is-better 哲学的代价。
所以它最适合谁？SSH 远程持久会话，这是它的核心价值，目前少见同类方案。Claude Code 社区里很多人就拿 tmux 保持会话，长任务断线不丢进度——不过 Claude Code 在 tmux 里得额外配置，SSH 下还可能闪烁，官方离开终端主推的其实是 Remote Control 那套。还有多窗格工作流、结对编程、CI 长任务、日志监控、无图形界面的服务器。推荐上，远程开发选 tmux 比较稳妥；追求零配置的新手，可以看 Zellij；纯本地配 WezTerm，其实未必需要它；重度用户，搭配 dotfiles 才舒服。
