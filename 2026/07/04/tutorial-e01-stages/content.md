## 内容摘要（7 阶段方法论全景）

> 总纲（思想地基）+ 6 个实施阶段。每一步都带着可运行的 demo 和真实团队数据，不是空讲。

### 阶段 0 · 总纲：思想转变 + AI 原理认知

- **做什么**：转变思想 + 懂 AI 原理——先拥抱 AI，再理解原理，才能精准交互
- **产出**：全员认知对齐（无强制文档，建议各角色先读自己手册的「角色定位」）
- **核心判断**：AI 能提效、能大幅扩展人的能力边界，但 **AI 不是万能**——最终依赖使用人的能力边界。**人 + AI，人是根本**
- **五个原理**：token 预测（解释幻觉，必须验证）/ 上下文 1M（稀缺资源）/ Agent = 大模型 + 工具 / REACT 循环（思考→行动→观察）/ 精准下达指令（给上下文、明目标）
- **两个极端都避免**：①抗拒 AI（被时代抛下，不是 AI 替代你，是用 AI 的人替代你）②盲目崇拜（产出不可控、质量崩塌）。正确姿态：**拥抱 + 验证**——信任但验证
- **落地行为**：解放思想（默认先想 AI 能怎么做）+ 把重复交给 AI（CRUD/模板/文档/测试/格式化）+ 把 AI 当协作者（资深实习生，委派但审查）+ 接受新分工（人转向定义问题/设计架构/审查验证/沉淀知识）

### 阶段 1 · 战略启动（Leader 主战场）

- **做什么**：目标量化 + 立项审批 + 争取资源（Leader 主战场）
- **产出**：转型计划书（立项审批）+ 战略汇报 PPT 启动版（要资源，用现状痛点 + 目标 + 试点计划；**此阶段还没有验证数据**）
- **核心判断**：战略启动 = 目标量化 + 分期路线图 + 组织保障 + 风险预案。没有量化的转型是玄学，没有路线图的转型会混乱，没有组织的转型推不动，没有风险预案的转型易翻车。**四件事齐备，才叫「启动」**
- **目标量化**：培训后 1 个月提效 10-20%（适应期）/ 2 个月 20-30%（复杂任务）/ 3 个月目标 +50%（人均产出，启动承诺；实际跑出多少见阶段5）
- **预算与 ROI（成本 4 块）**：①工具/API（人均月费 × 人数 × 月数）②培训（2 天全员脱产 + 讲师）③基础设施（大型团队，小团队可跳过）④推广运营。ROI 公式：回本月数 ≈ 总投入 ÷（人均月薪 × 提效等效人力），行业常见 3-6 个月回本
- **老板三问**（立项要回答）：①「要多少钱？」→ 给 4 块成本表 ②「多久回本？」→ ROI 公式 + 同行业参考 ③「失败了怎么办？」→ 试点可控（小范围）、可止损（3 个月没效果就回退）、沉没成本低（工具按月付、培训是能力沉淀）。**把「试点验证 + 可止损」讲清，比承诺数字更扎实**
- **路线图**：三期 9-12 周——第一期准备（约 3 周：解析项目/建规范/搭环境/Skill 仓库/培训全员）/ 第二期协调与测试（约 3-4 周：基础设施/核心能力闭环/试点跑通）/ 第三期优化与推广（约 3-5 周：基于反馈优化/全面推广/效果度量）
- **坑**：别在立项时承诺 +104%——那是阶段5 跑出来的结果，立项时你还没有。承诺目标值（如 +50%）+ 试点验证路径，更诚实也更有力

### 阶段 2 · 全员赋能

- **做什么**：工具选型（按角色）+ 全员培训到 100% + 规范资产化（CLAUDE.md/Skills/Hooks 入 Git）
- **核心判断**：选对工具 + 全员培训到 100% 覆盖 + 规范资产化。工具选错，产出差距显著（经验上可达数倍）；培训留死角就推不动；规范不沉淀就各搞各的。**三件事做到位，团队才算「被赋能」**
- **工具选型（按角色）**：开发者/工程师 → Claude Code（终端原生、自主执行、MCP/Skills/Hooks 生态完整、上下文管理强）；产品经理/非开发 → OpenAI Codex（云端委托 + ChatGPT 集成，不必碰终端，适合原型/需求验证）
- **培训 100%**：不留死角。全员分发角色手册（开发/测试/组长/产品各读各的），先读「角色定位」
- **规范资产化**：CLAUDE.md（项目记忆 + 规范）+ Skills（可复用能力）+ Hooks（自动执行）提交 Git——团队规范变成 AI 能读的资产。**这是团队级提效的关键杠杆——个体再强，规范不沉淀就复制不开**

### 阶段 3 · 基础设施（小团队可跳过）

- **做什么**：业务知识 RAG + 代码知识图谱 + Skill 仓库 + MCP 网关
- **核心判断**：让 AI 从「概率性盲读」升级为「确定性查证」。**四件套是为大代码库/复杂业务准备的，小团队可跳过**
- **跳过前提**：代码库不大（单仓库、几万行内）+ 项目少（没有多仓库微服务）+ 业务知识不算复杂 → 直接跳过，用 CLAUDE.md + grep + 良好代码组织就够。强行建基础设施是过度工程
- **适合**：多仓库微服务、百万行级代码、复杂业务知识库、跨团队协作的大型组织
- **业务 RAG**：让 AI 懂私有知识（产品手册/内部规范）。两阶段检索（多路召回 → CrossEncoder 重排）+ 多租户隔离
- **代码知识图谱**：让 AI 改代码前看到影响范围（CALLS/IMPORTS/EXTENDS 等关系），一次调用拿全调用链，不用 10 次查询。可靠 + 省 token + 解放小模型（企业成本杀手锏）
- **Skill 仓库 / MCP 网关**：团队能力复用 + 把企业服务暴露给 Agent

### 阶段 4 · 流程闭环与试点（核心）

- **做什么**：OpenSpec + Superpowers 串六阶段闭环 + AI 自动化测试 + 防偷改护栏
- **核心判断**：用 **OpenSpec（规范管理 WHAT/WHY）+ Superpowers（执行 HOW）** 串成六阶段闭环，配合 SDD（spec/plan/tasks 三产物）把「发现需求偏差」的成本从**改代码**左移到**改 Markdown**。关键：**tasks 清单让 Claude 中途退出后仍可断点续传**，子代理分工让探索/实现/审查各司其职
- **为什么闭环难**：单点用 AI 容易，端到端流水线撞三堵墙——①AI 初始分析不准（理解偏了）②上下文断（会话中断前面全丢）③需求偏差晚发现（改完代码才发现理解错，返工贵）。闭环流程就是拆这三堵墙
- **SDD 三产物**：`spec.md`（WHAT，可测试行为规格 WHEN/THEN）+ `plan.md`（HOW，含完整代码的实施指南）+ `tasks.md`（DO，可追踪 checkbox 任务清单）。**核心价值是「左移」**——发现需求理解偏差从改代码（昂贵）左移到改 Markdown（便宜一个数量级）
- **断点续传**：tasks 清单让 Claude 中途退出后，重进项目指定 change 目录，看 tasks 的 `[ ]`→`[x]` 就知道做到哪了
- **试点设计**：选意愿强的团队 + 业务典型项目；1-2 个团队（每组 3-8 人）+ 1-2 个真实需求，跑 4-8 周；成功标准（AI 代码占比达标/产出提升/质量不降/团队愿意继续用）；**试点的目的是「拿数据说话」——成功有数据推广、失败有原因可查**

### 阶段 5 · 推广与度量

- **做什么**：多 Agent 并行推广 + AI 代码占比度量（用数据证伪）
- **核心判断**：多 Agent 并行把单点提效放大为大规模，效果度量用数据证伪。推广靠各组落地真实场景 + 提炼共性方法论；度量靠 AI 代码占比。**没有度量的转型是玄学，推广不动的转型是孤岛**
- **为什么**：阶段4 跑通了闭环，阶段5 解决两件事——①放大（从试点到全员、从单任务到大规模重构）②证伪（用数据回答「到底提效了多少、质量降没降」）。**最危险的状态是「大家觉得有用但说不清提升了多少」**，这会让投入无法持续
- **度量方法（AI 代码占比）**：通过 Git 提交元数据识别。最可靠信号是 Co-authored-by trailer（AI 工具默认埋点）+ 风格学第二道防线（作者历史 n-gram 相似度复核）防伪造。双口径：提交占比 + 行数占比（后者更真实），支持按作者/模块/周下钻趋势
- **真实数据**：跑 ai-metrics demo 直接看到自己代码库里 AI 写了多少（**这是事后统计、相关性非因果**——不能 100% 归功 AI）

### 阶段 6 · 沉淀与复用

- **做什么**：Skill 范式沉淀 + 知识沉淀 + 自我改进循环（个体经验 → 组织资产）
- **核心判断**：个体经验不沉淀，人走了经验也走了。把推广中积累的能力固化成可复用的 Skill 范式、把规范/避坑沉淀成 AI 自动加载的知识、把「犯错」变成「自我改进」。**这是转型从「一次性项目」变成「持续进化能力」的关键**
- **Skill 范式（飞书各组精华整合）**：工具型 / 规范型 / 平台型 / 流程型 / 记忆型 / 诊断分析型 / 编排型——好的 Skill 有共同范式：description 要具体、写清「何时触发/何时禁止」、任务关键的用 `disable-model-invocation` + 显式调用
- **知识沉淀**：规范资产化（团队红线写进 `.claude/rules/`，AI 自动加载）+ 真实避坑（生产 bug 复盘 → 规则）+ 自我改进循环（犯错 → 规则 → 不再犯）
