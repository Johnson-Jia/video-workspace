第四件套，MCP 网关。把企业内部的服务零代码封装成 MCP 工具，供 AI Agent 调用——比如把注册中心里的内部服务直接暴露给 AI。但记住一条原则：命令航能搞定的别用 MCP。每个 MCP 工具的定义常驻烧 token，能用 gh、kubectl 完成的就别封装。MCP 只用于没有命令航等价物的场景，比如连接企业内部服务。最后回到开头的反常识——这集可以跳过。判断标准看三件事：代码库大不大、项目多不多、业务复不复杂。单仓库几万航内、没有多仓库微服务、业务知识不算复杂——请直接跳过本阶段，克劳德.md 加 grep 加良好代码组织就够，强行建基础设施是过度工程。多仓库、百万航、复杂业务的大型组织才值得投入。跳过的团队用 grep 加人审加 git diff 替代，能力降级但闭环能跑。
