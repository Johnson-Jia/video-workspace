# 段 2.1 微服务闭环·全景 + 前半

## 旁白（约 85s，~400 字）

多 Agent 并行是横向放大，同时干多个任务。更远的终局是纵向贯通——把非技术人员提需求、AI 全流程执行、部署上线，串成一条 Agent 微服务流水线。这是成熟期愿景，不是起步就建。结构是一个顶级 Agent 加六个专项 Agent。顶级 Agent 接收语音需求，做语义解析、任务分发、异常兜底。六个专项 Agent 各管一段，接口标准，按项目隔离权限。先看前三个：需求定位，调 RAG 和代码图谱，定位需求对应的项目和功能模块；接口规划，按接口规范规划，优先复用已有接口，避免重复开发；代码生成，调公共和项目级 Skill 加 RAG 业务数据，生成 Controller、Service、Mapper。

## 视觉设计（横向 vs 纵向对比 + 顶级 Agent + 6 专项流水线前 3 高亮）

- **横向 vs 纵向对比图**（左上）：横向 = 多 Agent 并行同时干多任务（横排 3 节点并列）/ 纵向 = 全流程贯通（语音需求 → AI 执行 → 部署上线，纵向流水线）
- **顶级 Agent 节点**（顶部中央）：接收语音需求 + 语义解析 + 任务分发 + 异常兜底（向下分发到 6 专项）
- **六专项流水线**（底部横向）：前 3 高亮（需求定位 → 接口规划 → 代码生成），后 3 灰色预告（自检查 / 测试 / 部署，下集讲）
- **警示条**：成熟期愿景，不是起步就建（避免空中楼阁）
- bg：hex_grid（避开 diamond_lattice/contour_lines，与相邻段异质）
- fx：冷色 aura + particle（蓝/紫，alpha≤0.22，禁划过类），≥3 元素
- 字体：渐变同色系（蓝紫渐变），text-shadow 深蓝 rgba(30,41,59,0.6)

## 数据有据

6 专项 Agent 流程来自 stage5 §2.1（微服务闭环）。前 3 高亮 = 需求定位（RAG+代码图谱）/ 接口规划（复用优先）/ 代码生成（Controller/Service/Mapper）。后 3 灰色 = 自检查/测试/部署（下一段 2.2 讲）。顶级 Agent 职责 = 语音需求 + 语义解析 + 任务分发 + 异常兜底。禁改禁编。
