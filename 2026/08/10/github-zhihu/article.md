### 一、AI 智能体 & 大模型基建

#### 1. [TencentCloud/TencentDB-Agent-Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory)

**项目简介：** 一个面向团队级 AI Agent 的"长期记忆中枢"。它把对话、文档、代码沉淀成四类可复用的记忆资产（Chat Memory、Skill、LLM-Wiki、Code-Graph），让多个 Agent 之间能共享、治理并复用同一套上下文，而不是各自为政、每次从零开始。本质上是给 AI 助手配一个"团队知识库 + 记忆管理层"。

**核心亮点：**
- **四类记忆资产建模**——把"聊天回忆、可复用技能、领域百科、代码图谱"分类治理，分别对应不同的检索与更新策略，比单一向量库更贴近 Agent 实际工作流。
- **本地优先 + 向量检索**——支持 embedding 与向量搜索，强调数据可控，适合对隐私和合规有要求的企业团队接入。
- **跨框架可装配**——定位为"插件式记忆层"，可与多种 Agent 框架配合使用，降低记忆能力重复造轮子的成本。

**快速上手：** 仓库为 TypeScript 实现，提供文档与示例。建议先看 README 中的架构图，理解四类资产的边界，再按文档部署本地实例并接入现有 Agent。

**适合人群：** 在做 AI Agent 产品、需要团队级记忆与知识治理的开发者与企业技术团队。

#### 2. [lyogavin/airllm](https://github.com/lyogavin/airllm)

**项目简介：** 一个让你在**单张 4GB 显存**的 GPU 上就能推理 70B 级别大模型的开源项目。它通过层级化的显存调度（把模型分层按需加载到 GPU、其余留在 CPU/硬盘），把"必须多卡才能跑大模型"的硬件门槛拉到了消费级显卡甚至集成显卡的水平。

**核心亮点：**
- **极致显存压缩**——核心卖点就是"4GB 显存跑 70B"，对硬件受限的研究者、学生、独立开发者非常友好。
- **支持主流开源大模型**——兼容 Llama 系列等常见开源模型体系，配合 LoRA / QLoRA 等微调能力使用。
- **训练 + 推理兼顾**——除了推理，项目也提供指令微调相关能力，适合做模型实验与小规模定制。

**快速上手：** Python 安装后，按 README 指定的加载方式把模型层级化部署即可，建议先在小模型上验证流程再上 70B。注意大模型推理速度会因显存换页而下降，适合"跑得动优先、速度其次"的场景。

**适合人群：** 显存有限但仍想体验或研究大模型的研究者、学生、独立开发者。

#### 3. [esengine/DeepSeek-Reasonix](https://github.com/esengine/DeepSeek-Reasonix)

**项目简介：** 一个原生构建在开源推理大模型之上的**终端 AI 编码 Agent**，定位为"常驻后台、持续可用"的命令行编程助手。它围绕 prefix-cache（前缀缓存）稳定性做了工程化设计，让 Agent 在长时间运行、反复调用相似上下文时保持响应稳定，不容易"跑着跑着崩"。

**核心亮点：**
- **终端原生体验**——基于 TUI/CLI 构建，键盘流操作，适合重度终端用户与 Vim/Neovim 党。
- **前缀缓存工程化**——把缓存稳定性作为核心设计目标，解决长时间常驻 Agent 容易出现的延迟抖动与缓存失效问题。
- **工具调用 + 工具链集成**——支持 tool use，可挂载文件读写、shell 执行等开发常用工具，形成完整的编码闭环。

**快速上手：** 提供 CLI 安装方式，启动后常驻终端即可交互；建议参考 README 的工具配置段，先把基础读写与执行工具接通。

**适合人群：** 习惯终端工作流、希望有一个常驻 AI 编码助手陪伴的后端 / 系统方向开发者。

#### 4. [vitali87/code-graph-rag](https://github.com/vitali87/code-graph-rag)

**项目简介：** 一个面向 monorepo（大型多语言代码仓）的 **RAG 检索增强方案**。它结合知识图谱与 AST（语法树）解析，让你能用自然语言查询、理解并修改跨语言的庞大代码库——把"AI 读代码"从"塞进上下文窗口"升级为"基于代码结构图谱的语义检索"。

**核心亮点：**
- **AST + 知识图谱双引擎**——用 tree-sitter 做多语言语法解析，再把符号关系组织成图谱，检索时既懂语法结构又懂语义关联。
- **MCP Server 形态**——以 MCP 协议提供服务，可直接接入 Claude Code 等支持 MCP 的 AI 编码客户端。
- **monorepo / 多语言友好**——专门解决大型仓库、多语言混合场景下的检索难题，而不是只针对单文件。

**快速上手：** Python 实现，按 README 配置图数据库后端（如 Memgraph），将 MCP Server 注册到你的 AI 编码客户端即可对目标仓库发起自然语言查询。

**适合人群：** 在维护大型 monorepo、需要让 AI 准确理解和改动跨语言代码库的工程团队与平台工程师。

> Star: 2,876 | Fork: 518 | 协议: MIT | 语言: Python | 本周涨幅: +237

#### 11. [firecrawl/pdf-inspector](https://github.com/firecrawl/pdf-inspector)

**项目简介：** 一个用 Rust 编写的**高速 PDF 检查、分类与文本提取库**。它的核心价值在于：能智能判断一份 PDF 是"扫描件（图片）"还是"文本型 PDF"，从而让下游系统据此决定走 OCR 还是直接抽文本——解决文档处理流水线里"无脑全量 OCR 又慢又浪费"的痛点。

**核心亮点：**
- **智能分类路由**——自动识别扫描件 vs 文本型 PDF，让 OCR 只作用于真正需要它的文档，大幅降低处理成本。
- **Rust 性能**——以 Rust 实现核心解析逻辑，吞吐高、内存稳，适合批量文档处理。
- **多语言绑定**——提供 Python / Node.js 等调用方式，便于嵌入现有数据管线。

**快速上手：** Rust 库 + 多语言绑定，按 README 在 Python 或 Node 项目中引入，传入 PDF 即可拿到分类结果与抽取文本。

**适合人群：** 做 RAG 知识库、文档数字化、企业内容处理的工程师，需要稳定高速的 PDF 前置处理环节。
