## style

清爽专业科技风·方法论图解。ch2a 是全片信息密度最高的方法论段——画布六格、四步使用法、两组清单、三坑，视觉以**结构感**优先：网格撑满画布、清单左右分栏、警示卡金边/红字，禁为居中而居中。动画克制（data-reveal stagger 逐格点亮），fx 只做氛围（静态光晕/脉冲锚点，禁划过类）。教程重内容轻视觉。

## mood

沉稳·警醒——前半（需求探索）平稳专业推进，画布六格依次点亮带出方法论的秩序感；后半（PoC→生产）转警示，「残酷的事实」「死在演示阶段的头号原因」「三个坑」逐步升温，红/金警示色加重，收束在高警醒位。不煽动、不夸张。

## color_direction

深蓝底 + 四色分工（蓝=方法论结构 / 金=关键强调 / 红=警示 / 蓝白=次要文字）：

| 用途 | 色值 | 角色 |
|------|------|------|
| 背景 | `#0F172A` | 深蓝主底（沉稳，让结构内容突出） |
| 方法论结构 | `#3B82F6` | 画布六格标题、五组工程关卡、章节标题、四步箭头 |
| 关键强调 | `#FBBF24` | 画布金边、价值假设数据、第 0 组金边强调、关键数字 |
| 警示 | `#EF4444` | 新手常犯错、死在 PoC 头号原因、三坑警示 |
| 蓝白 | `#E0E7FF` | 口径标注（虚构脱敏）/ 次要说明文字 |
| 中性 | `#94A3B8` | 注释 / 分隔 / 步骤序号 |

> 强色控制：蓝/金/红严格分工——蓝=结构与方法、金=价值与关键、红=风险与坑。红仅用于警示元素（边框/图标/标签），不做大面积底色。渐变文字禁白色端点，同色系高饱和（金 #FBBF24→#F59E0B→#FCD34D / 蓝 #60A5FA→#3B82F6→#93C5FD / 红 #FCA5A5→#EF4444→#F87171）。

## storyboard

### narrative_template

方法论双段递进（ch2a 章节段）：
1. 钩子锚点：FDE 最核心的肌肉，竟然不在写代码（反直觉转折，引出第二章）
2. 章引：第二章重点 + 甲方用 AI → 乙方进别人业务用 AI + 五件事说前两件
3. 头一件·需求探索：新手常犯错（进场就讲技术）→ 正确顺序 → 探索画布六格
4. 客服案例：六格填入虚构脱敏示意数据（四千工单/82%/不碰发送/95% 待验证）
5. 画布四步使用法：① 访谈填前两格 → ② 自己填第三格 → ③ 当面确认四五格 → ④ 定第六格最小范围
6. 第二件·从演示到生产：残酷事实（干净数据跑通 ≠ 能上生产）+ 第 0 组商务组织前提四项（金边强调头号死因）
7. 五组工程关卡：数据准备/合规审查/系统集成/验收标准/上线回滚，任何一组没过都别上线
8. 三坑警示收束：跳过约束上演示 / 价值假设没对齐 / 发力点贪大

## 视觉区域范式

### 场景 2：章引（~13s，第二章标题 + 五件事导航）

- **章节标题区**（data-reveal=0）：左对齐「第二章 · 进客户现场用 AI」+ 副题「FDE 区别于普通 AI 工程师的核心」
- **对照条区**（data-reveal=2）：左「自己团队里用 AI」（灰）→ 右「进别人的业务用 AI」（蓝）箭头对照
- **五件事导航条区**（data-reveal=5）：五胶囊横排撑满（需求探索/演示到生产/价值证明/干系人/汇报），前两格点亮金边、后三格暗态
- **fx-blink**：锚点点缀

### 场景 3：需求探索画布六格（~21s）

- **常犯错警示条区**（data-reveal=0）：红边小条「新手常犯的错：进场就讲模型讲技术」+ 正确顺序蓝条「先摸清业务痛点 → 再看 AI 接哪块」
- **画布六格区**（data-reveal=3 stagger）：2×3 网格撑满画布（业务现状/痛点清单/AI 发力点/价值假设/约束/下一步），每格蓝标题 + 金边卡，依次点亮
- **fx-pulse**：六格区域中心锚点

### 场景 4：客服案例填入（~19s）

- **案例标签区**（data-reveal=0）：蓝白口径胶囊「虚构脱敏 · 示意案例 · 非真实客户」
- **六格数据区**（data-reveal=2 stagger）：画布六格同结构，格内填客服案例数据（四千条工单/准确率约 82%/自动分流+草拟回复/95% 待验证/不碰最终发送/最小验证范围），关键数字金色
- **fx-blink**：数据锚点

### 场景 5：画布四步使用法（~30s）

- **标题区**（data-reveal=0）：左对齐「画布怎么用 · 四步」
- **四步流程区**（data-reveal=2 依次）：四卡横排撑满 + 箭头连接——① 访谈填前两格（去现场看，别只听领导）→ ② 自己填第三格（去掉 AI 接不了的）→ ③ 当面确认四、五格（价值假设+约束，证明价值的基准）→ ④ 定第六格（最小验证范围）
- **fx-pulse**：当前步骤卡锚点脉冲

### 场景 6：第 0 组商务组织前提（~23s）

- **残酷事实区**（data-reveal=0）：红色渐变大字「干净数据跑通了 ≠ 能上生产」+ 副题「死在 PoC 阶段的头号原因，往往不在工程」
- **第 0 组清单区**（data-reveal=3 stagger）：金边强调卡组 4 项（预算有没有立项/采购流程走到哪/推动者在不在位/验收口径书面确认）+ 顶部标签「第 0 组 · 商务组织前提」
- **fx-aura**：警示红光晕（alpha≤0.22）

### 场景 7：五组工程关卡（~9s）

- **关卡流水线区**（data-reveal=0）：五节点横排撑满宽度（数据准备→合规审查→系统集成→验收标准→上线回滚），蓝节点 + 箭头连接
- **结论条区**（data-reveal=3）：「任何一组没过，都别上线」金底强调条
- **fx-blink**：节点锚点

### 场景 8：三坑警示卡（~20s）

- **标题区**（data-reveal=0）：左对齐「三个最常见的坑」+ 红色警示图标
- **三坑卡区**（data-reveal=2 stagger）：三卡横排（跳过约束上演示→数据拿不出、没法上线 / 价值假设没对齐→目标错位、做完不买单 / 发力点贪大→验证周期失控），红边警示卡 + 坑名粗体 + 后果灰字
- **fx-pulse**：红警示锚点脉冲

## 动画策略

- **网格/卡片 stagger reveal**：data-reveal 错时（2-3s 间隔），opacity 0→1 + translateY 12px→0，600ms ease-out，同屏累积不消失
- **大字 fade-in**：opacity 0→1 + scale 1.04→1，600ms（克制）
- **箭头连接线**：静态呈现（reveal 后即完整），不做生长动画
- **fx-aura 静态光晕**：脉冲呼吸（opacity 0.4→0.6 循环），不划过不追线
- **fx-pulse / fx-blink**：锚点脉冲/闪烁点缀构图
- **禁**：fx-scan/fx-stream/fx-beam 划过类、粒子过载、3D 翻转、强切换
