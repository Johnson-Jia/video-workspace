### hook（~30s，反常识）
**旁白**：工具装好了，规范也写了，团队也培训了——可 AI 一上手还是出问题：问业务细节就瞎编，改代码看不见影响范围，骨干一调走经验也带走了。这集讲基础设施：给 AI 装上眼睛和记忆。但先说一句反常识——这集的内容，小团队可以跳过。

> 视觉：深蓝底 + 三痛点文字依次浮现（瞎编/看不见/留不住），最后大字「这集可以跳过？」反差钩子。fx 用 fx-aura 静态光晕（禁划过类）。

### intro（~30s，方法论）
**旁白**：基础设施四件套：业务知识 RAG、代码知识图谱、Skill 仓库、MCP 网关。它们解决三件事：让 AI 懂私有业务、看得见代码全貌、留得住团队能力。但这套东西是为大代码库、复杂业务准备的——多仓库、百万行代码、跨团队协作的大型组织才需要。小团队用 CLAUDE.md 加 grep 就够，别过度工程。

> 视觉：四件套 4 卡片横排（RAG / 代码图谱 / Skill 仓库 / MCP 网关），各列一句话职责。底部黄条「小团队可跳过」提示。data-reveal stagger。

### 段1 三个痛点（~70s，三卡片）
**旁白**：先讲为什么 AI 需要眼睛和记忆——三个痛点。
- 第一个，不懂业务。通用大模型没读过你的产品手册、内部规范，问到业务细节就幻觉——它需要业务知识 RAG，给它开卷考试。
- 第二个，看不见全貌。AI 改一个函数，不知道有几十处依赖它的返回类型，破坏性变更被悄悄合并——它需要代码知识图谱，改之前看到爆炸半径。
- 第三个，留不住能力。某个开发者很会用 AI，调走之后经验也跟着走了——它需要 Skill 仓库，把高频能力沉淀成团队资产。
- 三个痛点直接拖垮落地质量。四件套就是解决这三件事。

> 视觉：3 卡片纵排（不懂业务/看不见全貌/留不住能力），每卡：图标 + 痛点名 + 一句话 + 对应解法标签（RAG/图谱/Skill）。data-reveal stagger，每卡进入时左侧 fx-pulse-ring 脉冲锚点。

### 段2 业务 RAG（~80s，卡片 + 代码）
**旁白**：第一件套，业务知识 RAG。通用大模型不懂你的业务——产品手册、内部规范它都没读过。RAG 的做法是：先检索知识库片段，再喂给模型，让它开卷考试。
- 核心是两阶段检索：第一阶段多路召回，优先找全；第二阶段 CrossEncoder 重排，精度提上去。
- 还要做多租户隔离——把租户标识拼进过滤表达式，A 公司的知识 B 公司查不到，default 是全租户共享。
- 业务 RAG 让 AI 准确回答业务问题，幻觉大幅下降。这是给 AI 装上"业务记忆"。

> 视觉：左卡片（RAG 原理：知识库→向量→检索→模型），右代码块（milvus 两阶段检索伪代码，等宽字 + 语法高亮：注释灰/关键字蓝/字符串绿）。代码逐行 reveal。

**[代码块 reveal]**
```python

三路并发召回 → 按原文去重 → CrossEncoder 重排 → 过滤低分
# 多租户隔离
expr = 'corp_code in ["租户A", "default"]'
```

### 段3 图谱原理（~70s，图谱可视化，核心段）
**旁白**：第二件套，代码知识图谱——这集的重头戏。先说为什么用图谱，不用 RAG。
- AI 改代码常因为看不见全貌出事。传统做法要大模型发好几次查询，才能拼出一个函数的完整上下文。
- 代码知识图谱在索引期就把关系算好——一次调用拿全调用链。三个好处：可靠，漏不掉上下文；省 token，不用查十次去理解一个函数；还能解放小模型，工具干了重活，对顶级模型的依赖就降下来了。
- 图谱和 RAG 不是二选一，是分层共存：确定性的调用关系走图查询，语义相似走向量搜索，各管一摊。
- 索引分六步：扫描建目录、Tree-sitter 解析符号、跨文件类型传播、社区发现划功能域、执行流追踪、最后提取业务概念。

> 视觉：**知识图谱节点图**（核心组件）—— 圆形节点（Function/Class）+ 连线（CALLS/IMPORTS 边），节点按 Community 染色（认证域蓝/支付域绿），选中节点高亮 + 连线发光（fx-aura），展示"一次查询拿全调用链"。底部 6 阶段索引流水线（横向 6 圆点：扫描→解析→传播→社区→执行流→概念，依次点亮）。

### 段4 图谱工具 + 两条铁律（~75s，终端演示，核心段）
**旁白**：图谱建好，暴露给 AI 的是十四个工具，分三类：
- 理解类：看清结构，比如 context 看符号的 360 度视图。
- 变更类：评估影响，impact 算爆炸半径，detect_changes 把 git diff 映射到受影响符号。
- 查询类：自由 Cypher 图查询，补图谱的盲区。
- 有两条铁律，必须写进 AI 的指令：第一，改任何符号前必跑影响分析；第二，提交前必跑变更映射。这两条是基础设施能不能落地的命脉。
- 实测效果：某团队用它排查生产 bug，跨仓库定位调用链，累计排查 144 个 bug，覆盖率超过八成。

> 视觉：**impact 工具终端窗口**（深底 + 标题栏「Terminal — impact analyzer」）+ 风险等级卡片。

**[终端演示 reveal]**
```
$ impact --target UserService.validateToken
⚡ 爆炸半径分析中...
  d=1  直接调用者:  12 处  (AuthController, LoginRoute...)
  d=2  间接影响:    47 处
  风险等级: HIGH ⚠
  建议: 改返回类型前先跑 detect_changes
```

> 视觉续：终端打字动画（命令逐字 + 输出 fade-in）→ 风险等级 HIGH 红色脉冲锚点。底部两条铁律卡片（改前必跑 impact / 提交前必跑 detect_changes），金色边框 + 警示图标。

### 段5 Skill 仓库（~70s，卡片）
**旁白**：第三件套，Skill 仓库。把团队重复的工作流沉淀成可复用的 Skill——比如代码生成、自检查、测试用例。
- 关键是分两层：公共 Skill 放公司级通用能力，由架构组统一维护；项目级 Skill 只放检索逻辑加项目专属规则，由项目负责人维护。
- 降 Token 的诀窍在这：业务数据别塞进 Skill，而是入 RAG 向量库按需检索。项目级 Skill 保持极轻，只有规则加检索逻辑，不必每次把整个项目知识塞进上下文。
- 开源平台推荐 SkillHub，讯飞出品，Apache 协议，一条命令装到本地，适合想私有化治理的中大型团队。

> 视觉：两层架构图（上层公共 Skill 3 卡 / 下层项目级 Skill 3 卡），中间箭头 + RAG 向量库侧挂。data-reveal stagger。

### 段6 MCP 网关 + 跳过提示（~80s，卡片）
**旁白**：第四件套，MCP 网关。把企业内部的服务零代码封装成 MCP 工具，供 AI Agent 调用——比如把注册中心里的内部服务直接暴露给 AI。
- 但记住一条原则：命令行能搞定的别用 MCP。每个 MCP 工具的定义常驻烧 token，能用 gh、kubectl 完成的就别封装。MCP 只用于没有命令行等价物的场景，比如连接企业内部服务。
- 最后回到开头的反常识——这集可以跳过。判断标准看三件事：代码库大不大、项目多不多、业务复不复杂。单仓库几万行内、没有多仓库微服务、业务知识不算复杂——请直接跳过本阶段，CLAUDE.md 加 grep 加良好代码组织就够，强行建基础设施是过度工程。
- 多仓库、百万行、复杂业务的大型组织才值得投入。跳过的团队用 grep 加人审加 git diff 替代，能力降级但闭环能跑。

> 视觉：MCP 网关卡片（企业服务→MCP 封装→Agent 调用）+ CLI 优先提示。下半部分「跳过判断」决策卡（3 问：代码库大？项目多？业务复杂？→ 都否则跳过 / 都否则用 grep 替代）。决策卡用金边强调。

### CTA（~30s）
**旁白**：基础设施是给大团队的深水区武器，小团队跳过不丢人。下集讲闭环试点——OpenSpec 加 Superpowers，从需求到交付一条命令跑完，那是这套方法论真正的核心发动机。合集 12 集，点关注不走丢，教程仓库在评论区。最后问你：你的团队，代码库到了需要图谱的规模吗？

> 视觉：合集标识 + E06 预告卡（闭环试点 · OpenSpec + Superpowers）+ 「关注不走丢」CTA。
