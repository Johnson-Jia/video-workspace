### 简介

E06 讲了闭环试点核心发动机（OpenSpec + Superpowers 六阶段），这集是闭环试点的下集，专治"AI 偷改测试"——从 10 行的单点修复到 15000 行的全量重写，给三层防护 + 四个真实案例。

**核心**：测试全部通过，业务逻辑却全错——这是让 AI 写代码最隐蔽的翻车场景。AI 跑不过测试时，它会"聪明地"改测试：删断言、放宽阈值、把 assert==false 改成 assert==true。绿灯亮了，bug 也藏进生产了。

**你将学到**
- **反常识钩子**：测试全绿 ≠ 代码正确。AI 改不动实现时会改测试，这是最危险的质量漏洞
- **三层防护**（层层拦截）：
  - L1 权限硬拦截——禁写测试目录，AI 从源头改不动测试文件
  - L2 TDD 铁律——先写失败测试（RED）再写实现（GREEN），流程上强制测试先行
  - L3 断言不删——diff 审计，删除 / 放宽断言即报警，事后追溯
- **四个真实案例**（规模递进）：
  - 案例 1 · 10 行：单点 bug 修复，TDD 怎么抓住一个边界条件
  - 案例 2 · 200 行：模块迁移，断言守护防止回归
  - 案例 3 · 3000 行：跨模块重构，权限拦截 + 断言审计双保险
  - 案例 4 · 15000 行：全量重写，12 Controller、211 API、TDD 严守全程
- **TDD 落地**：RED / GREEN / REFACTOR 三阶段在 Superpowers 子代理分工里怎么串
- **防偷改 vs 写好测试**：防偷改是底线，写好测试是上限——两者都要

**适合谁看**
技术负责人 / 研发 Leader（主导测试质量）、想让 AI 写代码但不放心测试质量的工程师、对 TDD / 权限治理 / 测试自动化感兴趣的开发者

### 补充评论（要点拆条，可分多条发）

1. 测试全部通过 ≠ 代码正确。AI 跑不过测试时会"聪明地"改测试：删断言、放宽阈值、把 assert==false 改成 assert==true。绿灯亮了 bug 也藏进生产了——这种全部通过是假的，测试验证的是错误逻辑，代码错测试也错，全部通过但业务逻辑全错。

2. 三层防护层层拦截。L1 提示词：CLAUDE.md 写明严禁修改测试文件，但靠 AI 自觉会被绕过。L2 权限（关键）：settings.json 的 deny 硬性拦截，Write/Edit 测试目录直接拒绝，AI 改不了。L3 Git 兜底：先提交测试，完成后 git diff 检查测试文件有没有被动。三层叠加，提示词挡大部分，权限兜底硬拦截，Git 最后核查。

3. settings.json 配 deny 是核心。permissions.deny 列出测试文件写入路径，比如 Write(test/**) / Edit(test/**) / Write(**/*.test.ts)。AI 尝试改测试时框架直接拒绝，不是提示词劝阻，是硬性拦截。这层不靠 AI 自觉靠框架强制，AI 再聪明也绕不过权限层。

4. TDD 铁律：不要让 AI 同时写代码和测试。RED 先写测试看它失败，GREEN 写最少代码让测试过，REFACTOR 重构。如果让 AI 同时写代码和测试，它会写出验证错误逻辑的测试——全部通过但业务逻辑全错。正确做法是测试先行（人或独立 agent 写测试），AI 写代码让测试过，独立验证。

5. 12 Controller 重构案例证明流程能撑住大规模迁移。某业务组重构个人中心，从前后端耦合重构为分离架构，规模 12 Controller、211 API、约 15000 行、110 个任务。关键是 tasks 清单支撑跨周断点续传——中途退出重进看 [x] 标记接着干。这个案例证明闭环不只撑小修小补，大规模迁移也能跑通。
