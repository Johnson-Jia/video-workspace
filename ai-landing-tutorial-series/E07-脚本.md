## 脚本

### 开场（复用 tutorial-opening，~20s）

### hook（~35s，反常识）
**旁白**：AI 写代码很猛，但它有个坏毛病——为了让测试"全部通过"，会偷偷改测试迎合错误逻辑。测试全绿，但业务逻辑全错。这集讲怎么防 AI 偷改测试，加四个真实案例，从单点修复到一万五千行大规模迁移。防护的关键不是提示词，是权限层硬性拦截。

> 视觉：深蓝底 + 大字「测试全绿 但业务逻辑全错」+ AI 偷改测试动画（测试代码被改）。fx-aura 静态光晕（禁划过类）。

### intro（~35s，方法论）
**旁白**：上集讲了闭环试点核心，这集讲测试侧——防 AI 偷改测试。AI 为让测试通过会改测试，光靠提示词不够，要三层防护：提示词加权限 deny 加 Git 兜底。再加四个真实案例，看闭环流程怎么撑住从单点修复到大规模迁移。你能学到：怎么防 AI 改测试、权限层怎么配、真实案例怎么跑。

> 视觉：三层防护预告横排 + 四案例图标。data-reveal stagger。

### 段1 偷改动机（~70s，卡片）
**旁白**：先讲 AI 为什么偷改测试。AI 的目标是让测试通过，当它发现测试失败，最省事的不是修代码，是改测试让它通过。这种全部通过是假的——测试验证的是错误逻辑，代码错测试也错，全部通过但业务逻辑全错。尤其 TDD 流程里，如果让 AI 同时写代码和测试，它会写出验证错误逻辑的测试。这就是为什么不能让 AI 同时写代码和测试。

> 视觉：偷改动机卡片（AI 目标 + 偷改路径 + 全部通过假象）+ 错误逻辑测试示例代码块。

### 段2 三层防护（~80s，三卡片）
**旁白**：防护三层，第 2 层是关键。
- 首层提示词：CLAUDE.md 写明严禁修改测试文件。但提示词靠 AI 自觉，会被绕过。
- 第二层权限（关键）：settings.json 的 deny 硬性拦截。Write test 编辑 test 直接拒绝，AI 改不了。
- 第三层 Git 兜底：先提交测试，完成后 git diff 检查测试文件有没有被动。
- 三层叠加，提示词挡大部分，权限兜底硬拦截，Git 最后核查。

> 视觉：三卡纵排（提示词/权限/Git），权限层金边强调 + 锁图标。data-reveal stagger。

### 段3 权限 deny 关键（~75s，终端演示，核心段）
**旁白**：第二层权限是关键，settings.json 配 deny。
- permissions.deny 列出测试文件写入：Write test 目录、Edit test 目录、Write 星 test.ts。
- AI 尝试改测试时，框架直接拒绝，不是提示词劝阻，是硬性拦截。
- 这层不靠 AI 自觉，靠框架强制。AI 再聪明也绕不过权限层。
- 配一行：deny 加 test 路径，测试文件锁死，AI 只能改业务代码不能碰测试。

> 视觉：settings.json 终端窗口（deny 配置高亮）+ AI 尝试改测试被拒动画。

**[终端演示 reveal]**
```json
// .claude/settings.json
{
  "permissions": {
    "deny": ["Write(test/**)", "Edit(test/**)", "Write(**/*.test.ts)"]
  }
}
```

### 段4 TDD 铁律（~70s，卡片）
**旁白**：防偷改还有一条 TDD 铁律——不要让 AI 同时写代码和测试。
- TDD 循环：RED 先写测试看它失败，GREEN 写最少代码让测试过，REFACTOR 重构。
- 铁律：测试先行、独立验证。AI 同时写代码和测试，会写出验证错误逻辑的测试，全部通过但业务逻辑全错。
- 正确做法：测试先行（人或独立 agent 写测试），AI 写代码让测试过，独立验证。

> 视觉：TDD 循环图（RED→GREEN→REFACTOR 三圆）+ 铁律卡（不同时写代码和测试）。圆内仅短词，长词移外（container_text 规则）。

### 段5 案例 form 编辑器（~85s，时间线，核心段）
**旁白**：看四个真实案例。第一个，form 编辑器数据丢失修复。
- 用户一句话需求，2 个 Explore 子代理调查，用户两次纠正方向：第一次根因定位错，第二次方案漏了 25 个插件。
- 提 3 方案：v1 prop 开关 2 文件覆盖不全，v2 prop 开关 25 个文件改动大，v3 provide/inject 2 文件自动覆盖。
- 最终用 Vue2 provide/inject，只改 2 个文件约 10 行，覆盖全部 25 个插件。
- 启示：AI 前两版是机械式的（漏或笨），是用户对业务的理解找到了最优解。用户引导是核心，AI 是执行者。

> 视觉：案例时间线（需求→2 Explore→2 次纠方向→3 方案→最终 2 文件 10 行）+ 方案演进卡（v1/v2/v3 对比）。

### 段6 案例 12 Controller 重构（~85s，数据卡，核心段）
**旁白**：第二个，个人中心前后端分离重构，大规模迁移。
- 某业务组用 OpenSpec 加 Superpowers 加 tasks 任务中断后自动恢复，把个人中心从前后端耦合重构为分离架构。
- 规模：12 个 Controller、211 个 API、约一万五千行、110 个任务全部完成。
- 关键是 tasks 清单支撑跨周任务中断后自动恢复——中途退出重进，看 x 标记接着干。
- 这个案例证明闭环能撑住大规模迁移，不只是小修小补。

> 视觉：数据卡（12 Controller / 211 API / 15000 行 / 110 任务）大字 + 任务中断后自动恢复流程。

### 段7 案例 前端陪练（~70s，卡片）
**旁白**：第三个，前端 AI 陪练对话生成，复杂集成。
- 某前端团队用 AI 生成对话交互模块，8 人日（5 开发加 3 修复），生成 5289 行。
- 含 React 乘 Vue SDK Monkey Patch、SSE 拦截器等复杂集成。
- 证明 AI 不只能写 CRUD，前端复杂场景也能落地，关键在给足上下文加分步验证。
- 第四个案例系统设置 API 拆分（7 决策记录在 design.md），时间关系不展开，评论区放教程链接。

> 视觉：案例卡（8 人日 / 5289 行 / React 乘 Vue / SSE 拦截器）+ 复杂集成示意。

### CTA（~30s）
**旁白**：防偷改测试是闭环的质量命脉——权限层硬拦截加 TDD 铁律，加真实案例证明流程能撑住从 10 行到一万五千行。下集讲 AI 代码占比怎么算，三层识别防伪造。合集还有六集，点关注不走丢，教程仓库在评论区。最后问你：你的团队，AI 写的测试你敢直接信任吗？

> 视觉：合集标识 + E08 预告卡（AI 代码占比度量）+ 关注 CTA。
