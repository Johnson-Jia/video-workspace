**你将学到**
- **反常识钩子**：76.6% 怎么算？光数 Co-authored-by 不够，三层识别才能挡掉假信号

- **三层识别算法**（防伪造）：

- **事前估算 vs 事后统计**：估算公式 + 场景表（CRUD ~90% / 复杂 70% / Bug 70% / 平均 ~75%）+ 实测 76.6% 落区间

### 补充评论（要点拆条，可分多条发）

1. 76.6% 怎么算？光数 commit 里的 Co-authored-by 不够。VS Code Copilot 会对人手写的代码也自动加 trailer，光数 trailer 占比会虚高。要三层识别：Co-authored-by 初筛 + 风格学复核 + 注册表组合，把假信号层层挡掉。最危险的状态不是没用 AI，是大家觉得有用但说不清提升了多少——老板问提升了多少，你说感觉有，明年预算就没了。

2. 多 Agent 并行是规模放大器，三种玩法。agent-teams：六步流程加四种策略加项目注册表跨项目复用。psmux：一个终端驱动多个 Agent 并行开发不同端。code-review 多 Agent：Haiku 资格审查 + 5 个 Sonnet 并行专项审查 + 独立 Haiku 打置信度分，到 80 分才发评论。但 Windows 上同时跑 5 个 Agent 容易 fork 失败，建议 2-3 个起步。

3. 第二层风格学是反伪造关键。原理：每个开发者有独特的代码风格指纹，AI 生成的代码风格往往和作者本人不一样。算法四步：字符级 n-gram 切分 → TF 归一化 → 算余弦相似度 → 置信度 = 1 − 相似度。像本人手写的相似度高，可能是误标，降低置信度；不像本人的相似度低，确认是 AI。这样能挡住 VS Code Copilot 对手写代码加 trailer 这类误标。

4. 第三层注册表给双口径：提交占比 + 行数占比。行数占比更真实——一个 AI 提交可能改 500 行，一个手写提交改 5 行，光数提交数会低估 AI 占比。还支持按作者、按模块、按周下钻趋势，看哪个组哪个模块 AI 用得多。事前估算配事后统计：估算给方向（CRUD ~90% / 复杂 70% / Bug 70% / 平均 ~75%），统计给真相（实测 76.6% 落在区间内），两者独立。

5. 度量的本质：能被量化的才能被管理，能被管理的才能指引方向。拍脑门能蒙对一次，量化才能对齐一百次。企业级转型不是赌运气，每一分投入都要数据托底。度量不是为了证明 AI 有用，是为了让下一组决策有根。别指望一上来就跑出 76.6%——度量是逐步建的，先有业务覆盖率，再有 bug 排查覆盖率，最后才有 AI 代码占比。
