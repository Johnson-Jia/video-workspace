## 脚本

### 开场（复用 tutorial-opening，~20s）

### hook（~35s，反常识）
**旁白**：上集讲了防 AI 偷改测试。这集讲个更硬的问题——AI 代码占比七成六点六，这个数怎么算出来的？你可能会说，数 commit 里的 Co-authored-by 不就行了。但有个坑：VS Code 的 Copilot，会对人手写的代码也自动加 Co-authored-by。光数 trailer，占比会虚高。这集讲三层识别算法，怎么把假信号挡掉，算出真实的 AI 代码占比。

> 视觉：深蓝底 + 大字「76.6% 怎么算」+ Co-authored-by trailer 浮现 + VS Code Copilot 误标动画（手写代码被加 trailer）。fx-aura 静态光晕（禁划过类）。

### intro（~35s，方法论）
**旁白**：这集讲推广度量。两件事：多 Agent 并行把单点提效放大成规模，加 AI 代码占比度量用数据证明真提效。核心是三层识别：Co-authored-by 初筛，风格学复核，注册表组合。你能学到：多 Agent 怎么并行不炸，AI 代码占比怎么算才不被骗，事前估算和事后统计怎么配合。

> 视觉：两件事预告横排（多 Agent 放大 + 度量证伪）+ 三层识别预告（初筛/复核/组合）。data-reveal stagger。

### 段1 为什么度量（~60s，卡片）
**旁白**：先说为什么必须度量。最危险的状态不是没用 AI，是大家觉得有用但说不清提升了多少。这种状态投入没法持续——老板问提升了多少，你说感觉有，明年预算就没了。不可度量等于不可管理。所以阶段五要解决两件事：放大，从试点到全团队；证伪，用数据回答到底提效多少、质量降没降。没有度量的转型是玄学，推广不动的转型是孤岛。

> 视觉：双卡（"感觉有用"→预算没了 流程 / 不可度量=不可管理）+ 放大与证伪两件事图标。

### 段2 多 Agent 并行（~70s，三卡片）
**旁白**：放大靠多 Agent 并行，三种玩法。agent-teams：六步流程加四种策略加项目注册表跨项目复用。psmux：一个终端驱动多个 Agent 并行开发不同端。code-review 多 Agent：Haiku 做资格审查，五个 Sonnet 并行专项审查，独立 Haiku 打置信度分，到八十分才发评论。但有个坑：Windows 上同时跑五个 Agent 容易 fork 失败，内存不足，建议两到三个起步。

> 视觉：三卡纵排（agent-teams/psmux/code-review）+ Windows 2-3 个警示条（5 个 fork 失败）。布局 space-between 撑满画布。

### 段2.1 微服务闭环·全景+前半（~85s，流水线）
**旁白**：多 Agent 并行是横向放大，同时干多个任务。更远的终局是纵向贯通——把非技术人员提需求、AI 全流程执行、部署上线，串成一条 Agent 微服务流水线。这是成熟期愿景，不是起步就建。结构是一个顶级 Agent 加六个专项 Agent。顶级 Agent 接收语音需求，做语义解析、任务分发、异常兜底。六个专项 Agent 各管一段，接口标准，按项目隔离权限。先看前三个：需求定位，调 RAG 和代码图谱，定位需求对应的项目和功能模块；接口规划，按接口规范规划，优先复用已有接口，避免重复开发；代码生成，调公共和项目级 Skill 加 RAG 业务数据，生成 Controller、Service、Mapper。

> 视觉：横向（多 Agent 并行）vs 纵向（全流程贯通）对比图 + 顶级 Agent 节点 + 六专项流水线前 3 高亮（需求定位→接口规划→代码生成），后 3 灰色预告。

### 段2.2 微服务闭环·后半+人机边界（~85s，流水线）
**旁白**：再看后三个专项 Agent。自检查，对照开发规范校验生成代码，输出报告加修改建议，直到合规。测试，生成自动化测试用例并执行，不过则回传代码生成 Agent 优化。部署，测试通过后自动提交代码、部署到对应环境。底座是 RAG 向量库存业务数据，加代码知识图谱存代码结构，这俩在阶段三建。整个流水线的定位是 AI 主导重复工作，人聚焦核心决策。但必须先跑通阶段零到五——思想、战略、培训、基础设施、闭环试点、度量，有了数据和规范底座再演进，否则就是空中楼阁。人机边界：人定义需求加审核决策，AI 执行全流程。

> 视觉：后 3 Agent（自检查→测试→部署）+ 数据底座（RAG 向量库+代码图谱）+ 人机边界（人定义需求+审核 / AI 执行）+「先跑通阶段零到五再演进，否则空中楼阁」警示条。

### 段3 首层 Co-authored-by（~70s，终端演示，核心段）
**旁白**：度量靠 AI 代码占比。最可靠的信号是 Co-authored-by——AI 工具默认会在 commit 末尾埋 trailer。首层初筛：解析 commit message，匹配六个 AI 工具名：claude、copilot、cursor、chatgpt、codeium、gemini。命中就判 AI，置信度一点零。但这层有个缺陷：VS Code Copilot 会对手写代码也自动加 trailer，会误标。所以光靠首层，占比会虚高。

> 视觉：终端窗口（commit message + Co-authored-by trailer 高亮）+ 6 工具名名单 + 误标缺陷红框警示。

**[终端演示 reveal]**
```
commit a1b2c3d
Author: Alice <alice@team.com>

    feat: add user profile API

    Co-authored-by: Claude <noreply@anthropic.com>
```

### 段4 第二层 风格学（~85s，算法流程，核心段）
**旁白**：第二层是反伪造关键——风格计量学。原理：每个开发者有独特的代码风格指纹，AI 生成的代码风格往往和作者本人不一样。对被 Co-authored-by 标记的提交，算它和作者本人风格画像的余弦相似度。算法四步：字符级 n-gram 切分，TF 归一化，算余弦相似度，置信度等于一减相似度。像本人手写的，相似度高，可能是误标，降低置信度；不像本人的，相似度低，确认是 AI。这样能挡住 VS Code Copilot 对手写代码加 trailer 这类误标。

> 视觉：算法四步流程图（n-gram→TF 归一化→余弦相似度→置信度=1−sim）+ 相似度高/低两分支（高→误标降置信 / 低→确认 AI）。圆/胶囊内仅短词，长词移外（container_text 规则）。

### 段5 第三层 注册表 + 双口径（~60s，卡片）
**旁白**：第三层注册表把前两层组合，给出最终判定。还有个细节：双口径。提交占比加行数占比。行数占比更真实——一个 AI 提交可能改五百行，一个手写提交改五行，光数提交数会低估 AI 占比。支持按作者、按模块、按周下钻趋势，看哪个组哪个模块 AI 用得多。

> 视觉：注册表组合卡（首层+第二层→最终判定）+ 双口径对比（提交占比 vs 行数占比，行数占比金边强调）。

### 段6 事前估算 vs 事后统计（~75s，表格，核心段）
**旁白**：占比有两种算法，要配合用。事前估算：推广前按场景估目标占比，用于设预期定考核。公式：AI 占比等于 AI 生成核心代码加 AI 辅助优化，除以总代码量。简单 CRUD 接口，AI 能干到九成；复杂业务逻辑，七成；Bug 修复加优化，七成。平均下来整体目标约七成五。事后统计：转型跑完后用度量工具算真实占比。实测七成六点六，落在估算区间内。估算给方向，统计给真相，两者独立。

> 视觉：估算公式 + 场景表（CRUD 90% / 复杂 70% / Bug 70% / 平均 75%）+ 实测 76.6% 落在区间标注。

**[场景表 reveal]**
| 开发场景 | AI 生成核心 | AI 辅助优化 | AI 占比目标 |
|---|---|---|---|
| 简单接口 CRUD | 80% | 10% | 90% |
| 复杂业务逻辑 | 50% | 20% | 70% |
| Bug 修复/优化 | 30% | 40% | 70% |
| 平均 | 53.3% | 23.3% | ~75% |

### 段7 量化效果（~70s，数据卡）
**旁白**：看全团队跑完的真实数据。人均代码产出加一倍多，加一百零四个百分点，同期人数还少了百分之九。Bug 占比降了十六点四个百分点，从三成八降到两成二。AI 代码占比七成六点六，简单 CRUD 到九成。测试用例生成快了五到十倍，从四到八小时压到十到三十分钟。词元消耗案例值降四成。这些是转型前后对比，不能百分百都算 AI 的功劳，需求加人员变动也有影响，但量级足以说明 AI 转型和显著提效强相关。

> 视觉：数据卡大字（+104% / -16.4pp / 76.6% / 5-10倍 / -40%词元）+ 转型前后趋势对比条。数据卡 width:100% 撑满画布。

### 段8 度量逐步建（~50s，阶梯）
**旁白**：最后提醒个坑——度量是逐步建的，不是部署工具就出数据。真实团队先有业务覆盖率，再有 bug 排查覆盖率，最后才有 AI 代码占比。别指望一上来就跑出七成六点六。先建可量化的业务指标，度量体系随转型成熟分阶段落地。

> 视觉：度量三阶段阶梯（业务模块覆盖→bug 排查覆盖→AI 代码占比）+ "别指望一上来 76.6%" 警示条。

### 段9 度量的本质（~40s，金句升华）
**旁白**：最后说一句度量的本质。能被量化的，才能被管理；能被管理的，才能指引方向。拍脑门能蒙对一次，量化才能对齐一百次。企业级转型不是赌运气，每一分投入都要数据托底——度量不是为了证明 AI 有用，是为了让下一组决策有根。

> 视觉：金句大字三阶梯递进（量化 → 管理 → 方向）+ "拍脑门蒙一次 vs 量化对齐一百次" 左右对比。深蓝底 + 金色渐变文字（同色系深金→暖金，禁白端点；文字渐变非 fx 光晕，不踩暖 alpha 坑）。fx-aura 静态低 alpha 衬底。

### CTA（~30s）
**旁白**：AI 代码占比是转型的数据底座——三层识别防伪造，事前估算配事后统计。下集讲 Skill 范式整合，怎么把个体经验变成组织资产。合集还有五集，点关注不走丢，教程仓库在评论区。最后问你：你的团队，AI 写了多少代码，能量出来吗？

> 视觉：合集标识 + E09 预告卡（Skill 范式整合）+ 关注 CTA。
