## 脚本

### 开场（复用 tutorial-opening，~20s）

### hook（~30s，反常识）
**旁白**：一个 SFTP 推送任务静默挂了九个月，客户才发现。不是没报错，是代码把异常吞了，任务自报成功。这种坑，怎么让它永远不再发生？这集讲把个体经验变成组织资产——七种 Skill 范式加自我改进循环，让 AI 犯过的错，自动变成团队规范。

> 视觉：深蓝底 + 大字「静默 9 个月」+ SFTP 任务报绿（成功）但实际挂掉动画。fx-aura 静态光晕（禁划过类）。

### intro（~30s，方法论）
**旁白**：这集讲沉淀复用。前五集能力长在个人身上，某个开发者很会用 AI，人走了经验也走了。阶段六把个人会用变成团队资产：Skill 复用、知识沉淀、避坑库、自我改进。你能学到：七种 Skill 范式怎么选，规范怎么资产化，AI 怎么自我改进。

> 视觉：个体→组织 对比（个人脑→团队仓库）+ 沉淀三路预告（Skill/知识/自我改进）。data-reveal stagger。

### 段1 为什么沉淀（~50s，卡片）
**旁白**：先说为什么必须沉淀。前五个阶段，能力主要长在个体身上。如果这些能力不沉淀成组织资产，人员流动会让能力流失。阶段六的核心是把个人会用变成团队资产。三条路：Skill 复用，把高频操作做成共享技能；知识沉淀，把规范和避坑写成 AI 自动加载的规则；自我改进，让 AI 犯错后自己更新规则。

> 视觉：双卡（个人脑 vs 团队仓库）+ 沉淀三路图标（Skill 复用 / 知识沉淀 / 自我改进）。

### 段2 七种 Skill 范式（~90s，七卡片，核心段）
**旁白**：七种 Skill 范式，各管一摊。工具型，封装高频开发动作，像 SQL 查询、CRUD 生成，业务开发团队最爱。规范型，让 AI 输出符合团队设计规范，前端团队用它统一 Token。平台型，低代码搭建，严格触发条件加接口白名单，绝不猜测写操作。流程型，AI 分析变更生成规范提交，自动提交。记忆型，持久化记忆跨会话复用，按项目隔离。诊断分析型，只读分析不改代码，性能诊断、慢 SQL 定位，跟工具型会改代码的有别。编排型，自己不实现，把多个 Skill 串成流水线，像 devflow 编排 OpenSpec 加 Superpowers 成六阶段。

> 视觉：7 卡片网格（工具/规范/平台/流程/记忆/诊断/编排）+ 每卡团队类型 + 一句话核心思路。编排型金边强调（devflow）。

### 段3 规范资产化（~50s，终端演示）
**旁白**：规范资产化，三条红线示例。其一，租户隔离，所有 SQL 每表必带 corp_code 字段。其二，MQ 和定时任务的 finally 必须清理上下文，否则数据串企业。其三，事务必须指定管理器。这些写进 rules 目录，AI 自动加载，新代码强制，旧代码宽容。

> 视觉：终端窗口（rules/ 三条红线代码）+ AI 自动加载动画。

**[终端演示 reveal]**
```
// .claude/rules/ 三条红线（AI 自动加载）
// 1. 租户隔离：所有 SQL 每表必带 corp_id
// 2. MQ/定时任务 finally 必须清理上下文
finally { ExecutionContext.setContextMap(null); }
// 3. 事务必须指定管理器
@Transactional(transactionManager = "transactionManager")
```

### 段4 真实避坑（~60s，案例卡，核心段）
**旁白**：真实避坑，来自生产 bug 复盘。最典型的是静默吞异常。代码里 catch 吞掉异常，然后无论如何都调 handleSuccess，任务自报成功。某 SFTP 推送任务就这么静默挂了九个月，客户才发现。修复方法是 catch 必须重抛或转 Error，失败必须调 handleFail。关键集成任务必须有外部健康检查，不能只信任务自报成功。这些避坑写进规则，AI 自动加载，同类问题不再重犯。

> 视觉：案例卡（❌ 静默吞异常代码 + 9 个月时间线）→ ✅ 修复代码 + 外部健康检查。

### 段5 自我改进循环（~60s，流程图，核心段）
**旁白**：自我改进循环是这套方法论的精华。让 AI 犯错后自己更新 CLAUDE.md。流程是：AI 犯了个错，你告诉它刚才那个错误是因为 X，它自己更新 CLAUDE.md 添加规则防止类似情况。下次再遇到，AI 自动避开。这样工具的失败自动转化为团队规范的进化。不是人去维护规则，是 AI 边用边学，规则越用越厚，团队越来越强。

> 视觉：自我改进循环图（AI 犯错 → 人指出 → AI 更新 CLAUDE.md → 下次自动避开 → 循环箭头）。

### 段6 六大共性方法论（~50s，六卡片）
**旁白**：十三个组的实战提炼出六大共性方法论。其一，规范知识资产化，先沉淀 AI 能读的说明书。其二，Skill 沉淀工作流，高频能力做成 Skill 共享。其三，OpenSpec 加 Superpowers 规范驱动，探索不是浪费是最高效的慢。其四，录制加 AI 生成，人做一遍 AI 看会批量复制。其五，多 Agent 并行，单点提效放大成大规模重构。其六，业务知识库 RAG 调研。

> 视觉：6 卡片网格（资产化/Skill/OpenSpec/录制/多Agent/RAG）+ 每卡一句话。

### 段7 沉淀复用案例（~50s，数据卡）
**旁白**：看沉淀复用的真实效果。工具型 Skill，像 sql-query、crud-gen，新人调用即用，不必重复摸索。编排型 Skill，devflow 把规范驱动开发从口号变成团队默认工作流。避坑资产，静默吞异常写进规则，同类问题不再重犯。录制加 AI 生成，测试用例从四到八小时降到十到三十分钟。个体的会用变成组织的默认能力。

> 视觉：数据卡（测试 4-8h→10-30min）+ 4 类资产卡（工具/编排/避坑/录制）。

### 段8 组织资产本质（~30s，金句升华）
**旁白**：最后说一句，转型不是一次性项目，是持续进化的能力。回到总纲，人加 AI，人是根本——工具和方法论都会迭代，但转变思想、懂原理、拥抱 AI 始终是地基。把个体经验沉淀成组织资产，让人走经验不走。

> 视觉：金句大字「人 + AI，人是根本」+ 个体经验→组织资产 流向。fx-aura 静态低 alpha 衬底。

### CTA（~25s）
**旁白**：Skill 范式整合是转型的组织能力底座。下集讲度量实操，跑 ai-metrics 看 AI 占比。合集还有四集，点关注不走丢，教程仓库在评论区。最后问你：你的团队，高频操作做成 Skill 共享了吗？

> 视觉：合集标识 + E10 预告卡（度量实操 ai-metrics）+ 关注 CTA。
