### 简介

上集（E08）讲了「AI 代码占比怎么算」的方法论，这集直接把工具跑给你看。光数 commit 里的 Co-authored-by 不够——VS Code Copilot 会给人手写的代码也自动加 trailer，占比虚高。怎么挡掉假信号？三层识别 + 风格学反伪造。

这集是推广度量的实操集：clone 仓库、跑 `python main.py`、看真实报告，整个过程 0 配置开箱即跑，换成你自己的仓库路径就能复用。

**你将看到**
- **L1 Co-authored-by 初筛**：commit trailer 匹配 6 大 AI 工具名（claude / copilot / cursor / chatgpt / codeium / gemini），第一道筛子
- **L2 风格学反伪造**（重头戏）：n-gram + 余弦相似度，判断「这段代码像不像作者本人手写」——挡掉被误标 trailer 的代码，这是最关键的一层
- **L3 注册表组合判定**：把 L1 + L2 的结果按规则组合，输出双口径（提交占比 vs 行数占比）的最终数据
- **python main.py 实跑**：从 clone 到出 Markdown/HTML 报告，全流程演示，附 Excel 模板让你直接对老板汇报
- **换自己数据**：把 main.py 里 REPO 指向你的仓库路径，立刻得到你团队的 AI 代码占比——零改代码

**为什么必须三层**
单看 Co-authored-by 会被工具自动加的 trailer 误导；单看风格学又会漏判。三层递进校验，每层挡一类假信号，最后给出来的数字才经得起老板和审计追问。

**适合谁看**
技术负责人 / 研发 Leader（要用数据证明转型 ROI）、想知道「我们团队 AI 到底写了多少代码」的工程师、对 n-gram / 余弦相似度 / 度量体系感兴趣的开发者

### 补充评论（要点拆条，可分多条发）

1. 为什么光数 Co-authored-by 不够。VS Code Copilot 有个机制，对你手写的代码也自动加 trailer，于是手写代码被算成 AI，占比虚高。要真实度量，必须识别哪些 Co-authored-by 是真 AI 写的，哪些是误标。ai-metrics 用三层识别算法挡住误标——这是这集的核心动机。

2. 三层识别每层干一件事。第一层 Co-authored-by 初筛，commit message 含 AI 工具名（claude / copilot / cursor / chatgpt / codeium / gemini 六大工具）就判 AI，置信度 1.0。第二层风格计量学复核，算这个 AI 提交的代码风格跟作者本人手写画像有多像，像本人降置信度（可能误标），不像确认 AI。第三层检测器注册表组合前两层给出最终判定，前一层粗筛，第二层反伪造，第三层收口。

3. 风格学是反伪造的关键。算法分四步：把代码切成字符级 n-gram 提风格特征 → TF 归一化去掉高频词干扰 → 算这个提交跟作者风格画像的余弦相似度 → 置信度等于一减相似度。越像本人，置信度越低（越可能是误标）；越不像本人，置信度越高（越确认是 AI）。

4. 示例仓库准备了三类提交演示这个算法。Alice 的干净提交（风格 A）用来建 Alice 的风格画像；Alice 的 AI 提交（风格 B 加 Co-authored-by）跟画像差异大，置信度高确认 AI；Alice 的误标提交（风格 A 加 Co-authored-by）跟画像更像，置信度被降下来——这一类就是 Copilot 自动加 trailer 误标的，被风格学挡住。三类提交把算法的判断逻辑讲清楚了。

5. python main.py 开箱即跑。cd 进 demos/ai-metrics，pip install openpyxl，一条命令跑完。脚本自动生成示例 git 仓库和 Excel 数据，度量 AI 占比 + 算提效同比 + 出 Markdown / HTML 报告。换自己数据：AI 占比改 main.py 里 REPO 指向你的仓库；提效同比按 template.xlsx 模板录你的上线记录替换 sample_releases.xlsx。注意一点，真实数据的开发人员字段经常含多人写法不规范，demo 按逗号拆分去重做了简化，用真实数据人数会偏高约两倍，但上线、需求、Bug 的数量和占比趋势是准的。
