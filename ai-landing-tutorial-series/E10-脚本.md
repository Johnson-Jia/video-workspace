## 脚本

### 开场（复用 tutorial-opening，~20s）

### hook（~30s，反常识）
**旁白**：AI 代码占比怎么算？很多人的第一反应是数 commit 里的 Co-authored-by 标记。但这招有个大坑——VS Code 的 Copilot 对你手写的代码也会自动加上 trailer，手写代码被误标成 AI，占比虚高。这集跑 ai-metrics，用三层识别算法加风格学反伪造，把 AI 占比真实算出来。

> 视觉：深蓝底 + 大字「Co-authored-by 不够」+ Copilot 自动加 trailer 动画（手写代码被误标 AI 红✗）。fx-aura 静态光晕（禁划过类）。

### intro（~30s，方法论）
**旁白**：这集讲度量实操。前集讲了推广度量——数据证明转型有效，但那个数据怎么来的？这集手把手跑 ai-metrics，你能学到：三层识别算法怎么挡误标，风格学怎么反伪造，一条命令跑出 AI 占比和提效同比，还有怎么换成你自己的数据。

> 视觉：度量三步预告（AI 占比 / 提效同比 / HTML 报告）data-reveal stagger。

### 段1 为什么度量难（~50s，卡片）
**旁白**：先说为什么度量难。Co-authored-by 是 commit message 里标记 AI 工具的署名行，AI 写的代码会带上。但只数它不行——VS Code Copilot 有个机制，对你手写的代码也自动加 trailer，于是手写代码被算成 AI，占比虚高。要真实度量，必须识别哪些 Co-authored-by 是真 AI 写的，哪些是误标。这就需要更准的算法。

> 视觉：双卡（✗ 只数 Co-authored-by 虚高 / ✓ 三层识别真实）+ Copilot 自动加 trailer 示意。

### 段2 三层识别算法（~80s，三卡片，核心段）
**旁白**：ai-metrics 用三层识别算法。其一，Co-authored-by 初筛，commit message 含 AI 工具名就判 AI，置信度一点零。其二，风格计量学复核，算这个 AI 提交的代码风格跟作者本人手写风格画像有多像，用余弦相似度衡量。像本人，可能是误标，降置信度；不像本人，确认是 AI。其三，检测器注册表，组合前两层给出最终判定。前一层粗筛，第二层反伪造，第三层收口。

> 视觉：三卡片横排（① Co-authored-by 初筛 / ② 风格学复核 / ③ 注册表组合）+ 每卡一句话 + 置信度流向。

### 段3 风格学原理（~60s，原理图，核心段）
**旁白**：风格学是反伪造的关键。它的逻辑是：用代码本身像不像作者本人手写来复核。算法分四步。第一步，把代码切成字符级 n-gram，提取风格特征。第二步，TF 归一化，去掉高频词干扰。第三步，算这个提交跟作者风格画像的余弦相似度。第四步，置信度等于一减相似度——越像本人，置信度越低，越可能是误标；越不像，置信度越高，越确认是 AI。

> 视觉：四步流程图（n-gram → TF 归一 → 余弦相似度 → 置信度=1-sim）+ 相似度高→降置信/低→确认 AI 对比。

### 段4 三类提交演示（~60s，对比卡，核心段）
**旁白**：示例仓库特意准备了三类提交演示这个算法。第一类，Alice 的干净提交，风格 A，用来建立 Alice 的风格画像。第二类，Alice 的 AI 提交，风格 B 加 Co-authored-by，跟画像差异大，风格学维持较高置信度，确认 AI。第三类，Alice 的误标提交，风格 A 加 Co-authored-by，跟画像更像，风格学降低置信度，演示反伪造挡住误标。三类提交把算法的判断逻辑讲清楚了。

> 视觉：三栏对比卡（干净A建画像 / AI风格B确认 / 误标风格A挡住）+ 每栏置信度数值。

### 段5 实跑 main.py（~70s，终端演示，核心段）
**旁白**：实跑一遍。先打开终端，cd 到 demos/ai-metrics 目录，没装依赖的先 pip install openpyxl。然后一条命令，python main.py。脚本会自动生成示例 git 仓库和 Excel 数据，然后度量 AI 占比，算提效同比，最后生成 Markdown 和 HTML 报告。整个过程开箱即跑，不需要你准备任何数据。

> 视觉：terminal 打字 `cd demos/ai-metrics` → `pip install openpyxl` → `python main.py` + scan_line 逐行扫输出。

**[终端演示 reveal]**
```
cd demos/ai-metrics
pip install openpyxl
python main.py
# === 1. AI 代码占比度量（含风格学反伪造）===
# === 2. 提效同比 ===
# === 3. 生成报告（Markdown + HTML）===
```

### 段6 输出解读（~50s，终端）
**旁白**：看输出。第一部分是 AI 代码占比，提交占比和行数占比，还有每个作者有多少提交是 AI。第二部分是提效同比，按年份分，每年的上线条目、需求、Bug、参与人数、人均条目。第三部分报告生成完成，Markdown 和 HTML 两个版本都落在 workspace 目录。

> 视影：terminal 输出三段（AI 占比 / 提效同比 / 报告路径）+ scan_line 高亮关键数字。

### 段7 提效同比 Excel（~50s，数据卡）
**旁白**：提效同比靠 Excel。data 目录里有个 template.xlsx 录入模板，列是日期、定制或通用、应用、类型、jira_id、描述、开发人员。按这个模板录入你自己的上线记录，放到 data 目录，efficiency 模块就能解析算同比。示例数据是 2025 基线和 2026 推行 AI 之后，开箱就能看到对比效果。

> 视觉：Excel 表格卡（template.xlsx 列名）+ efficiency 输出（上线/需求/Bug/人均）。

### 段8 HTML 报告（~40s，截图）
**旁白**：报告这块，report 模块同时生成 Markdown 和 HTML 两个版本。HTML 版用 ECharts 做可视化，AI 占比饼图、提效同比柱状图，一眼就能看清趋势。给老板汇报直接拿这个 HTML 去讲，比一堆数字直观得多。

> 视觉：report.html 截图框（饼图 + 柱状图 ECharts 可视化）。

### 段9 换自己数据（~40s，终端）
**旁白**：换成你自己的数据。AI 占比，改 main.py 里的 REPO 指向你的 git 仓库。提效同比，按 template.xlsx 模板录你的上线记录，替换 sample_releases.xlsx。有一点要注意，真实数据的开发人员字段经常含多人、写法不规范，demo 是按逗号拆分去重做了简化，用真实数据时人数会偏高大约两倍，但上线、需求、Bug 的数量和占比趋势是准的。

> 视觉：terminal（REPO = "/path/to/your/repo"）+ 注意卡（人数偏高约2倍 / 趋势准确）。

### CTA（~25s）
**旁白**：度量实操是转型的数据底座，有了真实占比才知道转型到底见效没有。下集讲 Skill 仓库实操，四个 skill 加十三条规范，复制到 dot claude 即用。合集还有三集，点关注不走丢，教程仓库在评论区。最后问你：你的团队，AI 占比度量了吗？

> 视觉：合集标识 + E11 预告卡（Skill 仓库实操）+ 关注 CTA。
