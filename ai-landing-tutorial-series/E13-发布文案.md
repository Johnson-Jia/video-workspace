### 简介

E12 讲了汇报材料 AI 生成（5 类汇报 prompt + ppt-master 原生可编辑 PPT），这集是合集收官——AI 自动化测试实操，跑通 ai-test-frame。

**核心**：AI 写测试最大的坑是"虚假通过"——AI 幻觉让测试脚本看着跑通了，实际根本没验证到点子上，绿灯上线就翻车。ai-test-frame 让 AI 只生成 handler（编码期），运行期零 AI 确定性执行，根治虚假通过。

**你将学到**
- 五个关键思想：AI 只生成不执行 / 数据与代码解耦 / 注册中心模式 / 软断言 / 变量传递
- 八文件架构：registry 注册中心 / assertions 软断言 / base_page 测试基类 / runner 调度器 / handlers 处理器 / main 入口 / data 用例 / site 被测页——一个文件一个核心模块
- 注册中心模式：@register 装饰器登记用例类型，调度器自动发现，新增业务零改调度器（类引用延迟解析是关键细节）
- 数据驱动：用例在 data 目录是纯步骤 JSON，代码在 handlers，调度器按 type 路由，下划线 save_as 保存 + ${变量} 引用做步骤间传递
- 软断言对比硬断言：硬断言一条失败立刻停，软断言失败不中断加截图加收集，一条用例多个验证都跑完
- AI 只生成不执行：handler 由录制加 AI 转换加人审在编码期产出，运行期确定性执行，规避幻觉
- 实跑演示：python main.py 开箱跑，Playwright 打开自带商品管理页，通过两个失败零个
- 四步改造换你系统：改定位 / 改地址加登录 / 写 handler / 编用例

③ 注册中心模式（装饰器登记，调度器自动发现）
④ 软断言（失败不中断，截图 + 收集）
⑤ 变量传递（步骤间用例间都能传）

### 补充评论（要点拆条，可分多条发）

1. AI 写测试最大的坑是"虚假通过"。AI 幻觉让测试脚本看着跑通了，实际根本没验证到点子上，你以为是绿灯，上线就翻车。ai-test-frame 的核心思路是让 AI 只生成测试代码，运行期全是确定性执行，零 AI，从根上规避虚假通过。

2. 八文件架构，一个文件一个核心模块。registry 注册中心（装饰器登记用例类型）/ assertions 软断言（失败不中断加截图）/ base_page 测试基类（封装通用操作）/ runner 调度器（数据驱动按类型路由）/ handlers 处理器（具体业务）/ main 入口 / data 用例（运营编步骤）/ site 被测页（自带极简商品页开箱跑）。架构清晰，开箱即跑。

3. 注册中心是这套框架的灵魂。写一个装饰器 register 把方法登记进全局表，调度器按类型自动取。关键细节：类引用延迟解析——装饰器执行时类还没定义完，那时取会拿到空，所以放到调度器创建实例时再解析。新增业务模块写完注册，调度器自动发现，零改调度器代码。

4. 软断言对比硬断言。硬断言一条失败立刻停，后面的验证全跑不到。软断言相反，失败不抛异常不中断，自动截图收集结果，一条用例的多个验证都跑完，全记进报告。更贴近记录问题，不是一错就停。

5. AI 只生成不执行是整套框架最关键的思想。handler 由录制加 AI 转换加人审在编码期产出，运行期是确定性的数据驱动调度，零 AI。规避幻觉——AI 直接运行测试可能幻觉出虚假通过，AI 只负责生成代码，人审通过后运行期全确定性执行，根治虚假通过。
