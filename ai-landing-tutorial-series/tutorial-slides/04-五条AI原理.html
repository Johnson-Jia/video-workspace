懂 5 条原理,交互效率天差地别

不懂原理就下指令 = 瞎指挥;token 预测 / 上下文 / Agent / REACT / 精准指令
大模型本质是根据上文预测下一个 token——不是"理解"你的代码,而是基于海量模式生成最可能的续写,所以会"一本正经地胡说"(幻觉),必须验证。
①
预测下一个 token
底层逻辑:基于上文生成最可能的续写。生成的是"看起来对"的,不是"验证过对"的
→ 解释幻觉,必须验证
②
上下文窗口 1M
虽大但仍会填满——大代码库/长会话/MCP 工具定义都撑爆它,填满后性能下降
→ 一切用法的约束原点
③
Agent = 大模型 + 工具
模型只能输出文字,组装工具后才能感知/改变环境;"先思考再行动"靠系统提示词
→ 非训练,是编排
④
REACT 循环
Thought(思考)→ Action(调工具)→ Observation(看结果)→ 循环 → Final Answer
→ 最广泛的 Agent 运行模式
⑤
精准下达指令
给上下文、明目标、定流程、要验证——像给聪明的实习生下指令
→ 模型越强,越需定义清楚
