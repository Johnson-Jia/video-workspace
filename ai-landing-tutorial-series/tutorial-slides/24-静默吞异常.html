静默吞异常,占 Bug 的 15%

来自生产 bug 复盘的真实避坑——catch 吞掉 + handleSuccess 在 try-catch 外,无论如何都"成功"
教训:关键集成任务必须有外部健康检查(数据时效性监控),不能只信任务自报成功。这类避坑写进 .claude/rules/,AI 自动加载。
❌ 反面写法
catch 吞掉 + 外部 handleSuccess
// catch 吞掉 + handleSuccess 在 try-catch 外 try { doBusiness(); } catch (Exception e) { log.info("出错了", e); } XxlJobHelper.handleSuccess(); // 无论如何都"成功" → 故障静默
→ 故障静默,9 个月才被发现
✅ 正解
catch 重抛或转 Error,失败 handleFail
// catch 必须重抛或转 Error,失败必须 handleFail try { doBusiness(); XxlJobHelper.handleSuccess(); } catch (Exception e) { log.error("任务失败", e); XxlJobHelper.handleFail(e.getMessage()); }
→ 失败可见,及时告警修复
🚨
惨痛案例:某 SFTP 推送任务因静默吞异常,停更 9 个月才被客户发现——不能只信任务自报成功
