AI 写的代码 ≠ 正确代码

合并 AI 生成的代码前,逐项核对——给人把关的清单(给 AI 用的审查 skill 在 code-review)
关键项用 Hook 强制(禁止改测试目录、提交前必跑测试),CLAUDE.md 只是建议,Hook 是确定性的。不让 AI 自己审自己。
一、正确性
逻辑符合 spec / 需求
  • 逻辑符合 spec(不是"能跑"就行)
  • 边界情况覆盖(空值、越界、并发、超时)
  • 错误处理真实(不是 catch 吞掉假装成功)
  • 没有验证错误逻辑的测试
二、影响范围
改动影响面已查清
  • 有图谱跑 impact,没有用 grep 列调用方
  • 没有破坏既有调用方(返回类型/接口签名)
  • 提交前跑 detect_changes / git diff 核对
  • 符合 CLAUDE.md / rules(命名、分层、提交)
三、安全 + 可维护
无注入/越权,改动可回滚
  • 敏感操作有授权检查(SQL 写、外部调用)
  • 无注入/越权风险(AI 常忽略权限校验)
  • 无硬编码(配置、密钥、定制逻辑)
  • 关键逻辑有注释,改动可回滚
💡 AI 时代 Code Review 四问(审核小组红线):① 提交者是否理解这段 AI 代码;② 是否过度工程;③ 调用的 API/库是否真实存在(防幻觉);④ 有无安全隐患——这四问比"代码能不能跑"更重要。
