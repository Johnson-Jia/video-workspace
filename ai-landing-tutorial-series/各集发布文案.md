## E02 · 思想转变：AI 转型第一步不是上工具，是转变思想

### 标题

```
AI 转型第一步不是上工具，是转变思想
```

> 备选（更冲击）：`AI 不是万能的——转型的第一步是懂这 5 条原理`

### 作品描述

AI 转型的第一步，不是上工具，是转变思想。

很多人觉得"AI 万能，把活全丢给它就行"——这个想法会让转型直接翻车。AI 不是万能的，这句话不是口号，是事实。但它能放大一个会用的人十倍。差别在哪？在这集讲的两块：**思想转变 + 5 条 AI 原理**。

**你将学到**
- **思想转变**：避开两个极端（抗拒 AI / 盲目崇拜），拥抱 + 验证的正确姿态
- **5 条 AI 原理速通**（精准交互的地基）：
  - ① 大模型本质 = 预测下一个 token → 所以会幻觉，必须验证
  - ② 上下文 1M = 约束原点 → 几乎所有最佳实践都围着它转
  - ③ Agent = 大模型 + 工具 → 让 AI 能感知和改变环境
  - ④ REACT 循环 = 思考→行动→观察 → AI 自主完成复杂任务的奥秘
  - ⑤ 精准下达指令 = 给上下文 / 明目标 / 定流程 / 要验证
- 收尾：**人 + AI，人是根本**——AI 扩展的是"会用 AI 的人"的能力边界

**为什么要懂原理**
不懂原理下指令就是瞎指挥。这 5 条懂了，你交互的方式会彻底变——这是后续所有阶段（工具/流程/度量）的地基。

**适合谁看**
想用 AI 提效的开发/测试/组长/产品，尤其是带团队的 Leader——思想转变要从你开始。

## E03 · 战略启动：怎么向老板要预算？AI 转型立项实操

### 标题

```
怎么向老板要预算？AI 转型立项实操
```

> 备选：`转型最大拦路虎不是 AI，是老板的预算审批`

### 作品描述

AI 转型最大拦路虎，不是 AI 行不行，是预算批不下来。老板一句"要多少钱、多久回本、失败了怎么办"，没准备的人当场卡住。

这集是 Leader 的主战场。思想就绪后怎么转？这集给立项实操全套——让老板放心批预算。

**你将学到**
- **目标量化**：阶梯目标（培训后 1 月 10-20%、2 月 20-30%、3 月 +50%）+ 目标前置公开承诺
- **4 块成本**：工具/API、培训、基础设施（小团队可跳过）、推广运营——算清总投入
- **ROI 公式**：回本月数 ≈ 总投入 ÷（人均月薪 × 提效等效人力），行业常见 3-6 月回本
- **老板三问**：要多少钱 / 多久回本 / 失败怎么办——答得出才批预算
- **失败预案**：止损线（3 月触发复盘）+ 回退（按月停/范围缩/Git 回退，沉没成本低）+ 复盘（方法错 vs 执行错）
- **数据诚信**：别在立项承诺 +104%——那是跑出来的结果，承诺目标值 + 试点路径更诚实有力

## E05 · 给 AI 装上眼睛和记忆：基础设施四件套（RAG + 图谱 + Skill + MCP）

### 标题

```
给 AI 装上眼睛和记忆：基础设施四件套实操
```

> 备选：`这集可以跳过？AI 转型基础设施判断指南`

### 作品描述

工具装好了，规范也写了，可 AI 一上手还是出问题——问业务细节就瞎编，改代码看不见影响范围，骨干调走经验也带走。

这集讲基础设施四件套：**给 AI 装上眼睛和记忆，让它从概率性盲读升级为确定性查证**。但先说一句反常识——**小团队可以跳过**，强行建基础设施是过度工程。

**你将学到**
- **业务知识 RAG**：先检索知识库再喂模型，让 AI 开卷考试——两阶段检索（多路召回→重排）+ 多租户隔离，幻觉大幅下降
- **代码知识图谱**（重头戏）：为什么用图谱不用 RAG——索引期算好关系，一次调用拿全调用链；6 阶段索引管线 + 14 个 MCP 工具 + 两条铁律（改前必跑 impact / 提交前必跑 detect_changes）
- **Skill 仓库**：团队能力复用——两层架构（公共 + 项目级）+ 业务数据入 RAG 降 Token
- **MCP 网关**：企业服务零代码封装——但 CLI 优先，能用命令行的别用 MCP
- **跳过判断**：单仓库几万行 + 无多仓库微服务 + 业务不复杂 → 直接跳过，CLAUDE.md + grep 就够

**真实案例**：某团队用代码知识图谱给 AI 装上代码眼睛，跨仓库定位调用链，累计排查 144 个生产 bug（覆盖率 80.4%）。

多仓库 / 百万行代码 / 复杂业务的大型组织（技术负责人、架构组）；小团队看完能判断我们是否需要——避免过度工程。

## E06 · 闭环试点：需求到交付一条命令（OpenSpec + Superpowers 六阶段）

### 标题

```
需求到交付一条命令：OpenSpec+Superpowers 六阶段闭环
```

> 备选：`AI 闭环试点的核心发动机：纠错左移提质量一个数量级`

### 作品描述

让 AI 写一段代码谁都会，难的是把需求到交付串成一条命令——AI 自己跑完，中间断了还能接着干。

多数人以为 AI 提效的关键是"让 AI 写更多代码"，这集说真正的发动机是**纠错左移**：把发现需求偏差从改代码左移到改一份 Markdown，交付质量提升一个数量级。这是合集里最有料的一集，闭环试点是整套方法论的核心发动机。

**你将学到**
- **三堵墙**：AI 初始分析不准 / 上下文断 / 偏差晚发现——串成端到端流水线会撞的三个坑
- **SDD 规范驱动开发**：三产物 spec(WHAT) / plan(HOW) / tasks(DO)，纠错左移的核心思想
- **OpenSpec 三概念四命令**：Spec 稳定 / Change 一次性 / Archive 归档 + explore/propose/apply/archive
- **六阶段流水线**：探索→规范→计划→TDD→验证→归档，每阶段一个 Superpowers skill 编排
- **断点续传**：tasks 清单状态机（[ ]→[in_progress]→[x]），中途退出重进扫 [x] 标记接着干
- **devflow 一条命令**：编排型 skill 把六阶段串起来 + 规则覆盖（rules/ 改写底层 skill 出口）
- **TDD + 子代理分工**：RED/GREEN/REFACTOR + Explore/实现/规格审/质量审四代理各司其职
- **随能力做减法**：入门 OpenSpec+Superpowers → 熟练 Superpowers → 精通 裸 Claude Code

**真实案例**：某业务组重构个人中心，12 个 Controller、211 个 API、约 1.5 万行、110 个任务，全靠 tasks 清单支撑跨周断点续传，中途退出重进看 [x] 标记接着干。

技术负责人 / 研发 Leader（主导闭环试点）、想让 AI 端到端跑通交付的工程师、对 spec-driven / Superpowers / OpenSpec 感兴趣的开发者

## E07 · 闭环试点下：防 AI 偷改测试（三层防护 + 四个真实案例）

### 标题

```
防 AI 偷改测试：三层防护+四案例从10行到15000行
```

> 备选：`测试全绿但业务全错——怎么防 AI 偷改测试？`

### 作品描述

测试全部通过，业务逻辑却全错——这是让 AI 写代码最隐蔽的翻车场景。AI 跑不过测试时，它会"聪明地"改测试：删断言、放宽阈值、把 `assert == false` 改成 `assert == true`。绿灯亮了，bug 也藏进生产了。

这集是闭环试点的下集，专治"AI 偷改测试"。从 10 行的单点修复到 15000 行的全量重写，给三层防护 + 四个真实案例。

**你将学到**
- **反常识钩子**：测试全绿≠代码正确。AI 改不动实现时会改测试，这是最危险的质量漏洞
- **三层防护**（层层拦截）：
  - L1 权限硬拦截——禁写测试目录，AI 从源头改不动测试文件
  - L2 TDD 铁律——先写失败测试（RED）再写实现（GREEN），流程上强制测试先行
  - L3 断言不删——diff 审计，删除/放宽断言即报警，事后追溯
- **四个真实案例**（规模递进）：
  - 案例1 · 10 行：单点 bug 修复，TDD 怎么抓住一个边界条件
  - 案例2 · 200 行：模块迁移，断言守护防止回归
  - 案例3 · 3000 行：跨模块重构，权限拦截 + 断言审计双保险
  - 案例4 · 15000 行：全量重写，12 Controller、211 API、TDD 严守全程
- **TDD 落地**：RED/GREEN/REFACTOR 三阶段在 Superpowers 子代理分工里怎么串
- **防偷改 vs 写好测试**：防偷改是底线，写好测试是上限——两者都要

**真实案例**：某业务组重构个人中心，15000 行代码、110 个任务全程 TDD 严守，三层防护下零断言被偷删，跨周断点续传不丢测试覆盖。

**适合谁看**
技术负责人 / 研发 Leader（主导测试质量）、想让 AI 写代码但不放心测试质量的工程师、对 TDD / 权限治理 / 测试自动化感兴趣的开发者

## E11 · Skill 仓库实操：4 skill + 13 规范复制即用（devflow / sql-query / crud-gen / code-review）

### 标题

```
Skill 仓库实操：4 skill + 13 规范复制即用（devflow/sql-query/crud-gen/code-review）
```

> 备选：`E09 讲了范式，这集给仓库——4 skill + 13 规范整套复制即用`

### 作品描述

E09 讲了 Skill 范式的七种方法论，这集把范式落地——一组适配 Claude Code 的 skill 加 rule 仓库，4 个核心 skill 加 13 条团队规范，整个复制到自己项目就能跑。

**核心设计**：skill 按需调用，rule 始终生效，AI 自动遵守——团队经验从「个人会用」变成「组织默认能力」。

**你将学到**
- **Skill vs Rule**：skill 是可复用工作流，AI 按需调用（你让它做某事，它加载对应 skill）；rule 是始终生效的规范，AI 每次自动遵守（不用你提）。一个按需，一个始终
- **三件套结构**：SKILL.md 入口（声明干什么 / 怎么触发）→ reference/scripts 按需加载（细节放这，省上下文）→ rules 覆盖（可选，改写底层 skill 默认行为，适配团队规矩）
- **4 核心 skill**（覆盖编排 / 工具 / 审查三类）：
  - devflow（编排型）：需求到交付 6 阶段流水线，调 OpenSpec + Superpowers，断点续传 + 规则覆盖
  - sql-query（工具型）：PostgreSQL 只读查询，三模式 + 安全护栏（只 SELECT / 走 SSH 隧道 / 强制租户隔离）
  - crud-gen（工具型）：读表结构自动生成分层增删改查代码（domain → controller 一套）
  - code-review（编排型）：AI 审查 + 红黄绿三级分级 + 自动套 rule 规范
- **13 规范 5 层**：入口 team-conventions（CLAUDE.md 用 @ 引用所有 rule，AI 自动加载）/ 接口层（api-response、service-dao）/ 质量层（error-handling、logging、testing）/ 数据层（database、batch）/ 并发层（async、distributed-lock）/ 工程层（git-branch、naming）
- **安装实操**：Mac Linux 用 `cp -r`，Windows 用 `xcopy`，或直接拖文件夹；装完在 CLAUDE.md 用 @ 引用 rule，AI 自动加载
